# 产品父单描述模板

创建或回写产品父单时按这份模板整理。没有信息的字段写“待确认”，并在“待确认问题”中说明谁来补、何时补。

```markdown
# 产品需求：<需求名称>

## 基本信息

| 字段 | 内容 |
|------|------|
| 需求来源 | <老板要求 / 用户反馈 / 竞品观察 / 数据问题 / 内部优化> |
| 产品负责人 | <姓名或企微 ID> |
| 当前状态 | <backlog / doing / for approve / approved / done> |
| 优先级 | <High / Middle / Low> |
| 关联材料 | <调研文档、原型、设计稿、数据看板等链接> |

## 背景

<2-4 句话说明为什么现在要处理这个需求。>

## 目标用户与场景

- 目标用户：<谁使用>
- 使用场景：<在什么情况下使用>
- 当前问题：<现在的问题是什么>

## 产品目标

- 目标 1：<可验证的业务或体验目标>
- 目标 2：<可选>

## 方案说明

<说明产品方案、关键流程、页面或交互变化。>

## 范围

### 这次包含

- <功能点 1>
- <功能点 2>

### 这次不包含

- <这次不做的内容>

## 验收标准

- <需要...>
- <完成后可以...>

## 调研记录

### 用户调研

<访谈、反馈、数据样本或观察结论。>

### 竞品或替代方案

<竞品、内部替代路径、现有方案对比。>

## 角色拆单建议

| 角色 | 是否需要子单 | 原因 |
|------|--------------|------|
| 设计 | 是/否 | <原因> |
| 前端 | 是/否 | <原因> |
| 后端 | 是/否 | <原因> |

## 子单列表

| 角色 | 子单 | 状态 |
|------|------|------|
| 设计 | <TAPD 链接或待创建> | <状态> |
| 前端 | <TAPD 链接或待创建> | <状态> |
| 后端 | <TAPD 链接或待创建> | <状态> |

## 风险与待确认问题

| 问题 | 负责人 | 截止时间 | 状态 |
|------|--------|----------|------|
| <问题> | <负责人> | <日期> | 待确认 |
```
