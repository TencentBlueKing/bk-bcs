# 迭代命名规范

## 规范定义

迭代名称必须遵循以下规范：

```
iteration-vMAJOR.MINOR.PATCH
```

各部分说明：

| 部分 | 含义 | 取值规则 |
|------|------|---------|
| `iteration-` | 固定前缀 | 必须以小写 `iteration-` 开头 |
| `v` | 版本号引导符 | 固定小写 `v` |
| `MAJOR` | 主版本号 | 非负整数，发生不兼容的重大变更时递增 |
| `MINOR` | 次版本号 | 非负整数，新增向后兼容的功能时递增 |
| `PATCH` | 修订号 | 默认固定为 `x`，表示该次版本下持续小版本迭代 |

## 命名示例

### 合法示例

| 名称 | 说明 |
|------|------|
| `iteration-v0.1.x` | 早期开发阶段的第一个 minor 迭代 |
| `iteration-v0.9.x` | 临近 1.0 发布的迭代 |
| `iteration-v1.0.x` | 1.0 正式版迭代 |
| `iteration-v1.2.x` | 1.x 系列的第二个功能迭代 |
| `iteration-v2.0.x` | 重大重构后的 2.0 首个迭代 |

### 不合法示例

| 名称 | 问题 |
|------|------|
| `iter-v0.1.x` | 前缀不是 `iteration-` |
| `iteration-0.1.x` | 缺少 `v` 引导符 |
| `iteration-v0.1.0` | PATCH 位应为 `x`，非具体数字 |
| `Iteration-V0.1.x` | 大小写错误，前缀和 `v` 必须小写 |
| `iteration-v0.1` | 缺少 PATCH 段 |
| `iteration-v0.1.x-beta` | 不允许附加后缀 |

## 校验规则（正则）

```regex
^iteration-v\d+\.\d+\.x$
```

如名称不匹配该正则，技能在执行规划前会输出警告，但不会终止流程，由用户判断
是否继续。

## 命名建议

- **同一发布周期内复用 PATCH=x**：例如 `iteration-v0.1.x` 内可包含多个开发循环
  （v0.1.0、v0.1.1 等小版本作为发布产物）。这种设计让"迭代"与"发布版本"解耦。
- **MAJOR 变更需团队共识**：MAJOR 递增意味着架构或对外接口的重大变化，规划新
  iteration-vX.0.x 前应有明确的版本演进规划。
- **MINOR 递增建议有节奏**：通常 1-3 个月一个 MINOR 迭代较为合适，避免 MINOR
  长期不动或每周递增。
