# 工作单元 AGENTS（发现与根索引）

> 与 `agents-merge.md` 配套：多数接入仓的项目记忆在**子目录** `AGENTS.md`，不在仓库根。  
> harness **默认只发现并索引**这些入口，**不覆写、不批量改写**其正文。

## 发现算法

在目标仓根（git 仓库根）执行：

```bash
git ls-files -- 'AGENTS.md' '**/AGENTS.md'
```

分类：

| 路径 | 类别 | 处置 |
|------|------|------|
| `AGENTS.md`（仓库根） | 根入口 | 按 `agents-merge.md` 理解 → 裁决 → 与 harness 短头合并 |
| 其它 `**/AGENTS.md` | **工作单元入口** | 记入清单；**默认不读写正文**（除非用户显式要求改该子树） |

非 git 仓：用文件系统遍历等价路径（排除 `node_modules`、`.git`、常见构建产物目录）。

## 根短头义务

若工作单元清单**非空**，根 `AGENTS.md` 短头须包含：

1. **「局部入口」**节（或等价标题）：表格或列表  

   | 路径 | 角色 |
   |------|------|
   | `${REL}/AGENTS.md` | 一句话（可从该文件首段理解后填写；不确定则写「见该文件」） |

2. **nearest 优先**句（语义必备，措辞可微调）：  

   > 修改某路径前，阅读该路径向上最近的 `AGENTS.md`；**局部约定优先于根**。根不替代工作单元入口。

若清单**为空**：不写空表。

## 禁止

- 为「统一格式」批量改写 / 删除工作单元 `AGENTS.md`  
- 把工作单元全文粘贴进根或 L2 五大组件文档  
- 用通用 standards 宣称已覆盖工作单元内的命令、禁令、参照文件  
- 未获用户明确要求，向工作单元 AGENTS **自动插入** standards 门闩  

## 报告字段

总结报告「工作单元 AGENTS」节：

- 路径列表（相对仓库根）  
- 根是否已建立索引 + nearest 句  
- （可选）用户是否要求改写某一子树（本阶段默认否）  

## 与 gardening

见维度 12：根未索引已有工作单元 → P1；园艺误改非根 AGENTS → 报告，默认不自动 restore 第三方正文。
