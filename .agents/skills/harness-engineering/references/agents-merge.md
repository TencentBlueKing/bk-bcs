# AGENTS.md 合并规程（先理解再裁决）

> generating 写根 `AGENTS.md`、gardening 巡检「项目记忆是否被误伤」时**共用**本文。  
> 适用于任意接入仓：**不绑定**某一仓库、某一正文格式或某一技术栈专有名词。  
> 工作单元（非根）发现与索引：见 [`agents-work-units.md`](agents-work-units.md)。

## 反模式（禁止）

- 跳过通读，直接用模板 0-A **整文件覆写**已有根 AGENTS  
- 用「匹配到某种语法 / HTML 注释 / 关键字」作为**保留或删除的充分条件**  
- 为凑行数删除经理解后判定为 `RETAIN-ENTRY` 的内容  
- 把通用 standards 正文当成可以替代各仓入口记忆的内容  
- **忽略**已存在的非根 `**/AGENTS.md`，只写根短头且不建索引  
- 批量改写 / 覆写子目录局部 `AGENTS.md`（默认只索引，见 `agents-work-units.md`）

## 分层落位（SSOT）

```
L1  根 AGENTS.md = harness 短头（概述/目录/关键/门闩/局部入口索引）
                 + 理解后应留在入口的项目记忆（格式不限）
L1b 工作单元 **/AGENTS.md = 各组件/子树真入口（默认不改正文）
L2  docs/harness/* = 导航 + 对 L1/L1b 的指针/短摘要
L3  standards / code
旁路 tooling.md = Skill/MCP/CLI 清单（不得堆在 AGENTS）
```

**格式不决定去留**；「对 Agent 在本仓做决策是否仍必要」才决定去留。  
**nearest 优先**：修改某路径前阅读向上最近的 `AGENTS.md`；局部约定优先于根。

## 第零步：工作单元清单（写根之前）

按 [`agents-work-units.md`](agents-work-units.md) 扫描并分类。  
非根路径 → 清单；根路径 → 进入下方「第一步」。  
短头若清单非空 → 必须含「局部入口」索引 + nearest 优先句。

## 第一步：理解根 AGENTS（必做）

若根 `AGENTS.md` **不存在** → 跳过本步理解，写短头（含工作单元索引若有）即可。

若存在 → **完整阅读**后回答，再改写。

### 1.1 基础七问

1. **地图**：哪些内容帮助定位「改哪里 / 看哪里」？  
2. **硬约束**：哪些是可执行的边界、禁令或必须遵守的原则？  
3. **交付与协作法**：如何增量交付、如何对齐已有实现、测试与提问纪律等？  
4. **元策略**：如何取上下文（检索/工具/语言/篇幅）？  
5. **验证入口**：宣称完成前应跑哪些仓库已有命令/脚本？  
6. **错位内容**：是否有应归 tooling 的清单？是否有与 harness 红线冲突的强制工作流措辞？  
7. **与短头重复**：哪些与即将写入的 harness 短头同主题（合并去重，而非当垃圾删）？

### 1.2 四件套归并检查（意图，不绑格式）

理解结束时须能指出（无则记「未见，细节可能在工作单元 AGENTS」）：

| 四件套 | 要能指出 |
|--------|----------|
| **地图** | 目录、任务→路径、组件关系/数据流（若有） |
| **边界与禁令** | 勿碰 sibling、生成物、契约兼容、领域红线 |
| **做法与参照** | 具名参照文件、先读邻近实现、分层职责 |
| **诚实验证** | 命令、工作目录、无能力时的「勿声称」 |

四件套已存在于根 → 倾向 `RETAIN-ENTRY`（或细节在局部则根只索引）。  
**不得**用 standards 散文替换四件套。

将结果记入总结报告 **「AGENTS 理解」** 节。  
**禁止**跳过理解直接套模板覆写。

> 非规范示例（**勿**写入判定条件）：压缩索引行 / 章节散文 / 混合——一律先理解再归类。

## 第二步：意图类别（裁决结果）

| 意图类别 | 含义 | 落位 |
|----------|------|------|
| `RETAIN-ENTRY` | 入口决策仍需要 | 保留在根 AGENTS（短头之后；可用 `---` 分隔） |
| `MERGE-HEADER` | 与短头同主题的项目事实 | 融入短头，保留特有信息、去掉重复句 |
| `MOVE-TOOLING` | 工具/Skill/MCP 清单类 | 迁 `docs/harness/tooling.md`；AGENTS 可留指针 |
| `PROMOTE-SUMMARY` | 适合 L2 展开说明 | L2 短摘要；**L1 仍保留约束要点或原文** |
| `DROP` | 冲突 harness 红线（如强制 workflow-agent /「不允许跳过」）或确认无信息量 | 删除并在报告写明理由 |

启发式**仅可提醒勿漏读**，不得写成「匹配则必留 / 不匹配则必删」。  
不要求、不依赖任何 HTML/特殊描点注释。

## 第三步：合并算法（generating）

1. **第零步**：工作单元清单；计划根索引。  
2. **第一步**：若有根 AGENTS → 理解 + 四件套 + 去留表。  
3. 写 harness **短头**（模板 0-A）：概述、目录、关键、**局部入口索引（若有）**、nearest 句、编码前门闩。  
4. 按意图落位：`RETAIN-ENTRY` 在短头之后；`MERGE-HEADER` 并入短头；`MOVE-TOOLING` / `DROP` 按表执行。  
5. 对 `RETAIN-ENTRY`：**优先保持原文结构与措辞**；禁止为「更像模板」改丢可执行约束。  
6. **行数预算**：短头 prose 目标 ≤80（压重复）；`RETAIN-ENTRY` 与工作单元索引**不因压行数删除**；过长 → WARN，用户确认前不自动拆。  
7. L2：对 L1/L1b 只指针 + 极短摘要；验证命令对齐入口层（见 generating L2 要点）。  
8. 报告：「AGENTS 理解」+「工作单元 AGENTS」。

## 第四步：gardening（项目记忆 + 工作单元索引）

- **根记忆误伤**：基线中地图/硬约束/交付法/元策略/验证入口在工作区变弱或消失，短头仍在 → **P0**，按理解恢复（配合维度 9-clean，不恢复强制 workflow）。  
- **工作单元未索引**：存在非根 `**/AGENTS.md`，根无索引表/列表且无 nearest 优先语义 → **P1**，提案补索引（角色列可先「见该文件」）。  
- **误改局部正文**：相对基线改写了非根 AGENTS 且非用户明确要求 → **P1**（报告「禁止园艺改局部」；默认不自动 `git restore` 第三方内容）。  
- **禁止**：仅凭关键字行数/注释自动整文件 restore；未理解用模板覆写根 AGENTS。

## 与其它规程的边界

| 主题 | 权威 |
|------|------|
| 工作单元发现与索引 | `agents-work-units.md` |
| 门闩文案 / 短头最小结构 | `assets/harness-spec-template.md` 模板 0-A |
| Skill/MCP/CLI 清单 | `tooling.md` + project-owned / tool-dependencies |
| IDE Rules | `standards-compliance.md` |
| 强制 workflow 残留 | gardening 维度 9-clean（主要清根） |
| 根记忆 + 索引巡检 | gardening 维度 12 + **本文** |
