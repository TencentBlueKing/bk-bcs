## 技术规范

> 确认目标项目的技术栈，用于选择对应的规范预设。
> 自动检测优先，检测结果展示给用户确认；未命中时通过提问引导选择。
>
> **按 `$PROJECT_DOMAIN` 选择提问分支：**
> - `$PROJECT_DOMAIN == code-project`：使用 TS-01～TS-08（代码技术栈提问）
> - `$PROJECT_DOMAIN == skill-tooling`：**跳过 TS-01～TS-08**，仅使用 TS-09（Skill 规范适用性确认）
> - `$PROJECT_DOMAIN == mixed`：TS-01～TS-09 均提问

### 技术栈确认（code-project / mixed）

> 仅当 `$PROJECT_DOMAIN == code-project` 或 `mixed` 时提问。

| 编号 | 问题 | 级别 | 默认值 |
|------|------|------|-------|
| TS-01 | 项目前端框架？（Vue 3 / React / 其他 / 无前端） | 阻塞 | 自动检测（package.json） |
| TS-02 | 前后端接口协议？（Proto+gRPC-Gateway / tRPC / REST+OpenAPI / GraphQL / 其他） | 阻塞 | 自动检测（go.mod / *.proto） |
| TS-03 | 后端语言和框架？（Go+go-micro / Go+tRPC-Go / Java+Spring / 其他） | 阻塞 | 自动检测（go.mod） |
| TS-04 | 是否需要特定技术栈的规范文档？（可多选预设列表） | 非阻塞 | 按检测结果自动选择 |

## 提问组织建议

向用户提问时，遵循以下原则：

1. **一次性提出**：将所有待确认问题整理为一份清单，避免碎片式逐条追问
2. **按优先级排列**：阻塞性问题在前，非阻塞性问题在后
3. **提供默认值**：非阻塞性问题附带默认值，让用户可以快速确认或调整
4. **分组呈现**：按组件分组，结构清晰

### 提问模板

```markdown
为了生成完备的 Harness Engineering 规范文档，需要确认以下信息。
标注"必填"的问题需要您回答，其他问题如无特殊要求可使用默认值。

### 基础信息（必填）
1. ...
2. ...

### 上下文工程
3. ...（默认值：xxx）
4. ...（默认值：xxx）

### 架构约束
5. ...（默认值：xxx）

...

如果某些问题暂时无法回答，可以先跳过，后续通过"定向修正"功能补充完善。
```
