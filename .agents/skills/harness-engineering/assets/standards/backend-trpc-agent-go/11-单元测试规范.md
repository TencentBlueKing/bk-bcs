## 十一、单元测试规范


### 11.1 Mock LLM 模型

```go
package mock

import (
    "context"

    "github.com/trpc-go/trpc-agent-go/model"
    "github.com/trpc-go/trpc-agent-go/model/message"
    "github.com/trpc-go/trpc-agent-go/tool"
)

// MockModel 实现 model.Model 接口，用于单元测试
type MockModel struct {
    responses []model.Response
    idx       int
}

func NewMockModel(responses ...model.Response) *MockModel {
    return &MockModel{responses: responses}
}

func (m *MockModel) Chat(ctx context.Context, msgs []message.Message, tools []tool.Tool) (model.Response, error) {
    if m.idx >= len(m.responses) {
        return model.Response{Content: "任务完成"}, nil
    }
    resp := m.responses[m.idx]
    m.idx++
    return resp, nil
}
```

### 11.2 Tool 单元测试（Table Driven）

```go
func TestSearch(t *testing.T) {
    tests := []struct {
        name    string
        args    SearchArgs
        wantErr bool
        errMsg  string
    }{
        {
            name: "正常搜索",
            args: SearchArgs{Query: "Go 泛型", MaxNum: 5},
        },
        {
            name:    "关键词过长",
            args:    SearchArgs{Query: strings.Repeat("a", 101), MaxNum: 5},
            wantErr: true,
            errMsg:  "query too long",
        },
        {
            name:    "数量超出范围",
            args:    SearchArgs{Query: "test", MaxNum: 0},
            wantErr: true,
            errMsg:  "max_num must be between",
        },
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            _, err := Search(context.Background(), tt.args)
            if tt.wantErr {
                assert.Error(t, err)
                assert.Contains(t, err.Error(), tt.errMsg)
            } else {
                assert.NoError(t, err)
            }
        })
    }
}
```

### 11.3 测试文件组织

```
internal/{module}/
├── tools/
│   ├── search_tool.go
│   └── search_tool_test.go      # Tool 直接单测
├── agent/
│   ├── my_agent.go
│   └── my_agent_test.go         # 使用 MockModel 的集成测试
```

### 11.4 测试规则

- Tool 函数直接单测，覆盖率不低于 80%
- Agent 集成测试使用 MockModel，覆盖正常流程和 Tool 失败场景
- 禁止在单测中真实调用 LLM API（费用不可控、结果不稳定）
- 边界条件必须覆盖：空输入、参数越界、下游不可用
