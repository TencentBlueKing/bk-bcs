## 十一、日志规范


### 11.1 日志级别

| 级别 | 使用场景 |
|------|---------|
| DEBUG | 开发调试信息，生产环境关闭 |
| INFO | 正常业务流程记录（启动、关键操作） |
| WARN | 非预期但可恢复的状况（重试、降级） |
| ERROR | 错误但服务仍可运行（请求失败、外部依赖异常） |
| FATAL | 不可恢复错误，服务需要退出 |

### 11.2 必须使用 Context 日志

Context 日志会自动关联请求调用链（trace id），是 trpc-go 中打日志的唯一正确方式：

```go
import "trpc.group/trpc-go/trpc-go/log"

// ✅ 正确：Context 日志，自动关联 trace id
log.InfoContextf(ctx, "user created: user_id=%s name=%s", userID, name)
log.WarnContextf(ctx, "retry attempt: count=%d", retryCount)
log.ErrorContextf(ctx, "query db failed: %v", err)

// ❌ 错误：非 Context 日志，丢失链路信息
log.Infof("user created: %s", userID)

// ❌ 严禁：绕过日志框架
fmt.Printf("user created: %s\n", userID)
```

### 11.3 日志规则

| 规则 | 说明 |
|------|------|
| 禁止打印敏感信息 | 密码、Token、身份证号等不得出现在日志中 |
| 请求日志 | 关键操作记录入参摘要（非完整 body）和耗时 |
| 错误日志 | 包含完整错误链（`%v` 或 `%+v`） |
| 避免高频日志 | 循环内不打 INFO 日志 |
| Service 层记录 | 错误在 Service 层记录一次，Handler 层不重复记录 |
