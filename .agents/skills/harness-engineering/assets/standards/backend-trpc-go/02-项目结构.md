## 二、项目结构


```
{project}/
├── proto/                         # Proto 接口定义（单一事实源）
│   └── {module}.proto
├── stub/                          # trpc-cli 生成代码（禁止手改）
│   └── {package}/
│       ├── {module}.trpc.go       # Server/Client 接口
│       └── {module}.pb.go         # 消息类型
├── cmd/
│   └── main.go                    # 服务入口
├── internal/                      # 内部业务逻辑（不对外暴露）
│   └── {module}/
│       ├── handler.go             # Handler 层（请求接收/参数校验/响应封装）
│       ├── service.go             # Service 层（核心业务逻辑）
│       └── repository.go          # Repository 层（数据访问抽象）
├── conf/
│   └── trpc_go.yaml               # 服务配置
├── pkg/                           # 公共工具库（可跨服务复用）
├── Makefile
└── go.mod
```

### 目录职责说明

| 目录 | 职责 | 可见性 |
|------|------|--------|
| `proto/` | 接口定义，单一事实源，修改需走评审 | 对外（定义契约） |
| `stub/` | trpc-cli 自动生成，禁止手动修改 | 对外（生成代码） |
| `cmd/` | 程序入口，初始化服务 | 对外 |
| `internal/` | 业务逻辑实现 | 仅当前项目可见 |
| `pkg/` | 通用工具库 | 可被其他项目引用 |
| `conf/` | 运行时配置，敏感字段通过环境变量或 Secret 注入 | 运维相关 |
