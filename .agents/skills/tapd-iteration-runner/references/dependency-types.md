# 需求依赖类型参考

> 本文档供 `tapd-iteration-analysis` 在 §3.3 识别技术依赖与业务依赖时参考。

## 技术依赖类型

关注需求实现层面的技术耦合：

| 类型 | 判定条件 | 示例 |
|------|---------|------|
| **共享模块依赖** | 多个需求涉及同一模块/组件的新增或修改 | 需求 A 新建用户模块，需求 B 需调用用户模块 |
| **接口依赖** | 一个需求提供 API/接口，另一个需求需要调用该接口 | 需求 A 提供订单查询接口，需求 B 的报表功能依赖该接口 |
| **数据依赖** | 一个需求产生的数据结构/表/字段是另一个需求的输入前提 | 需求 A 新增数据库表，需求 B 需要读写该表 |
| **配置依赖** | 一个需求引入的配置/环境变量是另一个需求运行的前提 | 需求 A 配置消息队列，需求 B 需要使用该队列 |

## 业务依赖类型

关注需求在业务流程上的先后约束：

| 类型 | 判定条件 | 示例 |
|------|---------|------|
| **前置功能依赖** | 一个需求的功能是另一个需求的使用前提 | 需先有"用户注册"才能做"用户登录" |
| **数据前提依赖** | 一个需求产生的业务数据是另一个需求的输入 | 需先有"商品录入"才能做"库存管理" |
| **流程顺序依赖** | 业务流程上存在明确的先后步骤 | "下单"必须在"支付"之前完成 |
| **权限/角色依赖** | 一个需求定义的角色/权限是另一个需求的前提 | 需先有"角色管理"才能做"权限分配" |
