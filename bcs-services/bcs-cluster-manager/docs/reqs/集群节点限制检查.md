## 需求背景

### 业务背景

- **当前问题**：TKE（腾讯云容器服务）的节点限制（`CreateClusterNodesLimit`，默认50）包含 master 节点和 worker 节点的总数。但当前 `CreateClusterValidate` 校验逻辑中，`maxNodeLimit` 直接使用 `CreateClusterNodesLimit` 作为 worker 节点数上限，未扣除 master 节点数量，导致用户创建的 master + worker 节点总数可能超过 TKE 实际限制，从而在 TKE 侧创建失败。
- **目标用户**：通过 bcs-cluster-manager 创建 TKE 集群的运维人员。
- **使用场景**：创建独立集群时，用户指定 master 节点列表和 worker 节点列表，系统需要校验总节点数是否在 TKE 限制范围内。
- **影响**：不做此修改，用户可能创建超出 TKE 限制的集群，导致底层 TKE 调用失败，产生难以理解的错误信息。

### 用户故事

作为 运维人员
我想要 创建集群时系统能正确计算 master + worker 节点总数是否在限制范围内
以便于 避免因超出 TKE 节点限制导致集群创建失败

### 核心功能点

### 详细功能描述

#### [F-001] CreateClusterValidate 中 maxNodeLimit 扣除 master 节点数

- **输入**：`req.Master`（master 节点列表）、`opt.CommonConf.CreateClusterNodesLimit`（配置的节点限制）
- **处理逻辑**：
  1. 确定基准值 `nodesLimit`：若 `opt != nil && opt.CommonConf.CreateClusterNodesLimit != 0`，则使用配置值；否则使用默认值 `common.CreateClusterNodesLimit`（50）
  2. 计算可用 worker 节点配额：`maxNodeLimit = nodesLimit - len(req.Master)`
  3. 校验 `len(req.Nodes) > maxNodeLimit`，超出则返回错误
- **输出**：校验通过或返回错误信息 `create cluster nodes count exceed maxNodeLimit: <可用配额>`
- **边界条件**：
  - `len(req.Master)` 为 0（托管集群场景）：`maxNodeLimit` 等于 `nodesLimit`，行为不变
  - `len(req.Master)` ≥ `nodesLimit`：见 F-002
- **异常处理**：
  - 超出配额 → 返回 `fmt.Errorf("create cluster nodes count exceed maxNodeLimit: %d", maxNodeLimit)`

#### [F-002] 减法下溢保护

- **输入**：`nodesLimit`（uint32）、`len(req.Master)`（int）
- **处理逻辑**：
  1. 计算 `result := nodesLimit - uint32(len(req.Master))`
  2. 若 `result > nodesLimit`（uint32 下溢标志），将 `result` 钳制为 0
  3. 当 `maxNodeLimit == 0` 时，`len(req.Nodes) == 0` 通过校验，`len(req.Nodes) > 0` 返回超限错误
- **输出**：`maxNodeLimit` 最小值为 0
- **边界条件**：
  - master 节点数 = nodesLimit → 可用配额 = 0，不允许任何 worker 节点
  - master 节点数 > nodesLimit → 可用配额 = 0，不允许任何 worker 节点

#### [F-003] 修复 AddNodesToClusterValidate 错误信息 panic bug

- **输入**：`opt`（可能为 nil）
- **问题**：当前错误信息中引用了 `opt.CommonConf.MaxNodeCount`，当 `opt == nil` 或 `opt.CommonConf.MaxNodeCount == 0` 时（此时 `maxNodeCount` 使用了默认值 `common.ClusterAddNodesLimit`），直接访问 `opt.CommonConf.MaxNodeCount` 会导致 panic 或显示错误值
- **处理逻辑**：
  1. 将错误信息中的 `opt.CommonConf.MaxNodeCount` 替换为已计算的 `maxNodeCount` 变量
- **输出**：错误信息 `cluster[<clusterID>] add NodesLimit exceed CloudMaxNodeLimit: <maxNodeCount>`

## 业务规则

### 业务逻辑规则

- **规则 R-001**：TKE 节点限制包含 master 节点和 worker 节点的总数，创建集群时 worker 节点可用配额 = 总限制 - master 节点数
- **规则 R-002**：当 master 节点数 ≥ 总限制时，worker 节点可用配额为 0，此时仅允许 0 个 worker 节点

### 数据校验规则

- `CreateClusterNodesLimit` 默认值为 50（`common.CreateClusterNodesLimit`）
- `ClusterAddNodesLimit` 默认值为 100（`common.ClusterAddNodesLimit`）
- 节点限制可通过 `opt.CommonConf.CreateClusterNodesLimit` 配置覆盖
